# Starforged Solo GM

An Electron desktop companion for solo **Ironsworn: Starforged** play. It combines a rules-aware campaign engine, OpenRouter-powered narration, campaign persistence, and optional local ComfyUI image generation.

## What it does

- Keeps character, asset, progress-track, connection, sector, clock, truth, and campaign-log state.
- Resolves moves and oracles through the local rules engine rather than model-authored arithmetic.
- Uses engine-issued roll IDs and transactional AI turns to prevent duplicate or partial mechanics.
- Saves campaigns atomically with a recovery backup and validates imported data at the IPC boundary.
- Supports optional portraits, locations, connections, and illustrations generated by a loopback ComfyUI server.

## Requirements

- Node.js 22 or newer
- An [OpenRouter](https://openrouter.ai/) API key for AI narration
- Optional: ComfyUI listening on the local machine for image generation

## Development

```bash
npm ci
npm run dev
```

Run the full local quality gate:

```bash
npm run verify
npm run playtest
```

The verification command runs engine/provider/updater/security/operability tests, TypeScript checking, bundled-data validation, the production renderer build, and the dependency audit policy.

## Packaging

```bash
npm run dist:win
```

Release tags are checked against `package.json`; CI must pass before the Windows artifact is published. See [docs/releases.md](docs/releases.md) for the release checklist and signing status.

## Data, privacy, and recovery

Campaigns and settings stay in Electron's per-user application-data directory. API credentials use the operating system's protected storage and are not returned to the renderer. Debug logging is off by default because it contains the full campaign context and model interaction; when enabled, logs rotate at 5 MB, retain at most four files, and expire after 30 days. Settings provides open, export, and clear controls.

Generated images are reference-aware across campaigns. A collector removes files no campaign or recovery backup references, while duplicate campaigns keep shared images until their final reference is removed.

For architecture and data-lifecycle details, see [docs/architecture.md](docs/architecture.md). For responsible disclosure and privacy notes, see [SECURITY.md](SECURITY.md).
